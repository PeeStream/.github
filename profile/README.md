## Official integrations

| Integration | What it does | Availability |
| --- | --- | --- |
| [WordPress & DooPlay](https://github.com/PeeStream/peestream-wp-dooplay) | Video embeds, controlled link migration, and publishing workflows for WordPress sites using DooPlay or a compatible theme. | **v1.0.4 beta candidate** · Staging only |
| DataLife Engine (DLE) | PeeStream video player, article-editor integration, and managed video-link migration for DLE. | **Private preview** · Public beta pending review |

> [!CAUTION]
> **Beta validation status:** Live CMS end-to-end testing has **not been performed** for the v1.0.4 beta candidates. Automated verification to date primarily uses mock and integration harnesses. Test beta builds only on isolated staging sites with complete backups. Do not deploy beta candidates in production.

## Upcoming integrations

Our roadmap includes two planned projects. Features and availability may change as development progresses.

- **PeeStream Browser Extension** — Send supported video links to your own PeeStream account using existing authentication and remote-import workflows.
- **WordPress Multi-Hoster & Self-Healing** — Manage multiple video sources per post, detect unavailable links, and attempt recovery through authorized, supported provider APIs.

Neither project has an announced public release date.

## For developers and publishers

Each public integration includes installation documentation, a changelog, and an issue tracker. For help with a specific plugin, open an issue in its repository and include the plugin version, CMS/theme/PHP/database versions where applicable, reproduction steps, and sanitized logs. Do not publish credentials, API tokens, or personal information.

### Release channels

| Channel | Meaning |
| --- | --- |
| **Stable** | An official general-availability release with its supported and verified compatibility documented. |
| **Beta** | Early-access software for staging validation; compatibility and behavior may change. |
| **Release candidate** | A candidate for stable release that still requires final verification. |

For security issues, use a repository's private vulnerability-reporting channel when available. Never post exploit details, tokens, or confidential infrastructure data in public issues.
